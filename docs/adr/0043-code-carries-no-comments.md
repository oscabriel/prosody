# Code carries no comments

A comment cannot be checked, so it drifts from the code beside it, and one that excuses a shortcut lets the shortcut stay. So the code has none, of any kind, a directive to a tool included: a decision is written as an ADR, a hack as an issue, and a word in the glossary, where each can be found and kept true. `pnpm check` enforces it twice, because a lint rule can be switched off by the very comment it forbids: the rule `prosody/no-comments` reports each comment in TypeScript, and `pnpm comments` reads every tracked source file itself, CSS, HTML, Dockerfiles and YAML among them. With no way to silence a tool in place, an error it reports is fixed in the code or in its configuration, as the service worker's types are now a compiler setting where they were a reference comment.
